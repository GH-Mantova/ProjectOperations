### CRLF hazard found and encoded into the prompt (Rule Zero)

`sot/04-data-model.md` is stored **CRLF** (4529 CRLF / 4529 LF — 100%). The generator writes
`relationship-map.md` **LF** (0 CRLF). A naive splice therefore produces a mixed-ending file.

The curated-tail sha is consequently line-ending-dependent:

- CRLF (Windows checkout): `bf7e8278f7c11e4ec0a668e35fe0240ad7b36d6550147d261f74fdfb5c4a42c8`
- LF-normalised: `6e0db192a89a8f3ce2aa4e776923add562749da7c4e3bdf544f658d862e82775`

The LF value is **byte-for-byte the sha PR #818 recorded on 2026-07-28**, which independently proves
(a) the curated tail has not moved in 22 days and (b) this sweep's instrument reproduces a known
positive. The staged prompt mandates `tr -d '\r'` before hashing and CRLF conversion before
splicing, with an explicit bare-LF assertion.
