What it does: Relationships stops being three hidden tabs under the Accounts tab
bar and becomes one four-panel screen -- log a contact, recent notes, going cold,
repeat business, all visible at once. Tab bars on that route go 2 to 1; panels
visible go 1 to 4. Going cold becomes cards, repeat business becomes proportional
bars, and win rate goes through the shared `formatWinRate` with no second
multiply-by-100.

The part worth knowing: the note form gains the contact picker it never had.
`relationships.service.ts` stamps `Contact.lastContactedAt` only when a
`contactId` is supplied, and until now no screen supplied one -- so per-contact
freshness never updated anywhere in the CRM. Changing the account resets the
contact selection, so a note can never be posted against a contact belonging to
a different account. No server change.

Approved knowing: one hex literal is added, `var(--color-teal, #005B61)`, which
the prompt's own item 5 and verification checklist both mandate for the
repeat-business bar; it is the same token `CrmBoardPage` uses. And the mock-up's
per-card tender count is NOT rendered -- no list-shaped route carries one, and
the card shows the open-opportunity count instead rather than firing a request
per row.

Not verified: no running app and no seeded database, so saving a real note and
watching `lastContactedAt` and the going-cold status move is unproven. That is
the one thing worth checking by hand on the deployed build, because it is the
point of the contact picker.
