before approval rather than discovered afterwards. This workflow gives anyone
who can comment "@claude" on this repository an agent holding contents: write
and pull-requests: write, spending my Claude tokens. On a private repository

The guards were read line by line before approval. The job is gated on
contains(comment.body, '@claude'), so no runner starts on any other comment;
timeout-minutes is 30; claude_args carries --max-turns 15; concurrency is one
run per issue or PR thread without cancel-in-progress, so a burst queues rather
than running in parallel and no half-finished run is cancelled mid-branch. The
permission block is exactly five entries and workflows: write is deliberately
absent, so the action cannot rewrite the conditions under which it fires.
actions/checkout is pinned to the version ci.yml already uses.

The workflow is inert until I add CLAUDE_CODE_OAUTH_TOKEN as a repository
secret. With the secret absent the action fails to authenticate, which is the
correct closed failure. No agent created, read or guessed it. The end-to-end
proof — comment @claude on a PR and confirm a run starts — is mine to perform
after the secret exists, and a green build here proves only that the YAML
parses.
