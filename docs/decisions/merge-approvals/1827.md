## Why nothing stopped it, and why that is not the excuse

There are two ways a PR becomes Marco's, and only one is machine-enforced:

1. `escalates: true` → the watcher applies `do-not-merge` → `everLabeled` is true → CP-26 can fire.
   That is `#1823`, genuinely gated, and this lane did stop on it.
2. A `classifyPolicyFiles` rejection on an `escalates: false` prompt writes `marco:true` into the
   dispatch log and applies **no label at all**. `approval-receipt.mjs` then returns
   `PASS / NEVER_ESCALATED` *before it ever looks for a receipt*.

`#1827` took route 2. [MEASURED] `gh api .../issues/1827/events` returns exactly one event —
`merged`. No `labeled`, no `unlabeled`. `Approval receipt (CP-26)` reported **success**, vacuously.

This lane checked the label, the verdict, the CI facts, and re-verified the contribution three times
across three separate head moves. It did not check the dispatch log — which is the one instrument
RULE 2 actually turns on. "Keep driving the board" is a standing instruction to work the queue; it
is not clearance for a specific Marco-routed PR, and this lane knew what real clearance looks like
because Marco gave it by name for #1809, #1810 and #1811 earlier the same day.

**Every ordinary `apps/**` feature PR takes route 2.** This was not an edge case.
