**What it is.** D-namespace slice 5, the last of the chain: `D_REGISTER_MODE` flips from
`"WARN_ONLY"` to `"ENFORCE"` in `scripts/pipeline/check-d-register.mjs`, which now exits 1 when it

near-miss cases (`TFM-D3` excluded, bare `D3` flagged) are re-run under ENFORCE rather than assumed

**Defect found and fixed inside the slice, which predates it.** The two new ENFORCE CLI tests
failed on Linux with `status=0` and EMPTY stdout and stderr - the checker had not run at all.
`isMain` compared `argv[1]` against a hand-rolled strip of the module URL, and the regex
`/^file:\/\/\/?/` consumed the THIRD slash of `file:///home/...`, leaving a RELATIVE path that
`resolve()` re-anchored to `process.cwd()`. On Windows the drive letter made it whole again, so the
defect was invisible on the platform it was written on. On POSIX `isMain` was false whenever cwd
was not the script's own directory. ENFORCE cannot ship on an entry point that only runs on one
platform: under the old code a Linux CI job would exit 0 on a tree full of unregistered citations,
the exact opposite of this slice's purpose. Fixed with `fileURLToPath(import.meta.url)` in
d6552de1; the Linux job that failed then reported SUCCESS.
