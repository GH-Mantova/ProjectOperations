**What it is.** Scope-cards S8a (TRAVEL_TIME_PORT_V1): the first time the ERP works out how long a
truck actually takes to reach a tip. Before this, loads per day, truck days and daily km were typed
in by hand on every waste line, and the only distance code in the repo was a straight-line
haversine used by the tip finder - so two estimators sizing the same run disagreed, and the 8-hour
cycle rule was written down nowhere in code. Twelve files: a new `travel-time.ts` exporting the
port, a `TravelEstimate` type, `StraightLineTravelProvider` and `deriveCycle()`;
`scope-waste.service.ts` resolving and snapshotting travel on create and update; the web tip picker
and a read-only cycle line badged "estimated, no route"; three new admin cycle-computation fields;
and the migration below.

**Migration, and why it is safe.** Additive only - nullable travel snapshot columns on
`scope_waste_items`, a nullable `map_location_id` FK, and three nullable settings columns. Nothing
existing is rewritten and no stored figure changes. To revert, drop the columns; every line keeps
the loads, truck days and km it already stores. `gate_allow: migrations` and `backfill: false` were
declared in the prompt.

**Typed values always win.** `loadsPerTruckPerDay` and `dailyKm` are derived only where the fields
are empty, so an estimator's own numbers are never overwritten by the estimate.
