chain. A rate table may now carry more than one VALUE column, so a transport type can state its
capacity per load beside its rate, and a waste line defaults its capacity from that matrix instead

that surfaces secondary VALUE columns, the waste service and controller reading them, a new admin

**Two defects fixed forward by this lane, neither cosmetic.**

1. **Colour literals.** `check-hex-ratchet.mjs` failed: the new `PlantTransportTypesPanel.tsx`
   carried ten colour literals (a file absent from the baseline must be clean) and
   `ScopeWasteTab.tsx` grew from eight to ten. Two of the literals sat behind token names that do
   not exist - `--border` and `--surface-raised` - so the hex fallback was doing the work and the
   theme could never override those colours. Mapped to the real tokens in `tokens.css`
   (`--status-danger`, `--status-warning`, `--surface-subtle`, `--surface-card`,
   `--border-default`, `--brand-primary`, `--brand-primary-light`). Only the two lines this PR
   added to `ScopeWasteTab` were touched, so its eight baselined literals stay put and this is not
   a disguised burn-down. Ratchet after: exit 0, "no file grew, no new file carries one", the new
   panel at zero. Commit e848d804.

2. **A compile break in three existing specs.** S9 makes `extraValues` a REQUIRED field on
   `ListedRate`. Three specs build `ListedRate` objects by hand: `rates-export.service.spec.ts`
   and `lookup-rate.handler.spec.ts` failed to COMPILE (TS2741, four sites between them) and
   `rate-resolver.service.spec.ts` failed a whole-shape `toEqual` that had gained a field. Fixed
   the fixtures rather than relaxing the type: the resolver always returns the field, documented
   as "always present, `{}` when the table has a single VALUE column", so a fixture that omits it
   describes a shape the resolver never returns, and making it optional would hide the next caller
   that forgets to read it. No production code changed in that commit. Commit f878a0a1.
