# Tender Folder Model Plan — SharePoint provisioning that files where humans look

**Cluster prefix:** TFM
**Plan status:** SLICE-0 (plan only — no product code in this PR)
**Authored:** 2026-08-18
**Decisions locked by:** Marco (ERP ideas decision log D34/D35/D36/D42; PR-Master run 2026-08-18)

---

## 1. Problem statement

The ERP has been provisioning tender folders into `1. Operations/1. Tenders/` since PR-64. The
tree currently holds **two entries** — `T260814-XXXX-Rev1` and `__connection_probe__` — while
every real tender lives at `2. Quotes/Quotes 2026/{month}/` (18 folders for August 2026 alone)
and every real job lives at `1. Jobs Won/` (35 entries). The ERP files perfectly into a tree
nobody opens.

Two failure modes made this state stick:

1. **Naming does not match the human template.** `T{YYMMDD}-{CLIENT-SLUG}-Rev{N}` versus the
   humans' `T2096 - Cornerstone - Grace LC Rothwell`. A revision bump also **rewrites
   `tenderNumber` on the same row** (`tender-number.service.ts:63`, confirmed by
   `tendering.controller.ts:468`), so any documents filed under the pre-revision folder are
   silently orphaned.
2. **Provisioning is autonomous and silent.** `sharepoint.service.ts:176
   ensureTenderFolderStructure` swallows per-category failures into a log line, and there is
   nothing on the tender page that says whether the folder tree was fully provisioned. When it
   isn't, uploads land wherever `ensureTenderCategoryFolder` re-creates a stub, and no human
   sees it.

This cluster fixes both while preserving the existing `SharePointFolderMapping` mapping (already
points at `1. Operations/1. Tenders`) and the existing MIG-3 legacy-copy scaffold (which is
blocked only on the missing `listFolderChildren` seam).

## 4. The target folder model

Root stays `1. Operations/1. Tenders/` (already the configured mapping; no config change).

```
1. Operations/1. Tenders/
    T260817 - Northshore/                    (T-YYMMDD then project; NO Rev, NO client)
        1. Plans, Scopes & Specs/
            01. Drawings/
            02. Specifications/
            03. Registers & BoQ/
            04. As Builts/
        2. Photos/
        3. Estimates & Calcs/
            Superseded/
        4. Suppliers/
        5. Compliance, WHS & Asbestos/
        6. Correspondence/
        7. Other/
        Quotes/
            {Client A}/                      (one per TenderClient)
                Superseded/
            {Client B}/
        Project Record.docx
```

Two properties of this shape matter as invariants:

1. **The folder name contains no Rev number, so a revision bump cannot strand it.**
2. **The client appears only under `Quotes/`.** Shared project material is stored once; each
   client's pricing stays separate. This is D36 and it is also a confidentiality property.

---

## 5. A live defect this cluster must fix

Marking a revision renames `tenderNumber` in place. `ensureTenderCategoryFolder` then builds a
path from the NEW number, fails to find the old folder, and **creates a fresh one — stranding
every document filed before the revision, silently.** This exists on main today, independent
of this work. **It is SLICE 2's first job.** It is a defect, not an improvement.

## 6. Ordered slices

Each slice has a `-HOLD.md` prompt file. All chain on **code artifacts** (never on this plan
document — D42 leaves the emitter PR open, so a gate on the plan would never open).

### TFM-S1 — `listFolderChildren` seam (MIG-3.5)

**Prompt:** `docs/pr-prompts/pr-tfm-s1-listfolderchildren-seam-HOLD.md`

Adds `listFolderChildren` to `SharePointAdapter`, `MockSharePointAdapter`,
`GraphSharePointAdapter`, exposes it on `SharePointService`, unblocks
`admin-imports.module.ts:45`. **Must handle Graph paging** — a folder with 250 or more
children must enumerate completely, with a test.

**Gate:** none (no predecessor).
**Primary artifact:** `apps/api/src/modules/platform/sharepoint.adapter.ts` containing
`listFolderChildren`.

### TFM-S2 — Folder naming + project name field

**Prompt:** `docs/pr-prompts/pr-tfm-s2-folder-naming-HOLD.md`

Adds a nullable `Tender.projectName` (Prisma), prefills it in `NewTenderWizard.tsx` from
`Site.name`, lets the estimator override before saving, derives the folder name
`T{YYMMDD} - {projectName}` (fallback to `Site.name` for rows without the field), sanitises
for SharePoint (strip characters Graph rejects, collapse whitespace, cap length, disambiguate
same-day same-project collisions). Fixes the revision-rename stranding by pinning the folder
path to the sanitized name at creation time and reusing it on rename.

**Gate:** none (parallel to S1; independent).
**gate_allow:** `migrations` (additive nullable column; `backfill: false`).
**Primary artifact:** `apps/api/prisma/schema.prisma` containing `projectName`.

If the migration + wizard change together exceed size 10, split into two chained slices
(S2a schema + backend derivation, S2b wizard UI) rather than exceed size.

### TFM-S3 — Template + unified category list

**Prompt:** `docs/pr-prompts/pr-tfm-s3-template-and-categories-HOLD.md`

Replaces the flat 11-category `DOCUMENT_CATEGORIES` with a single unified list that serves as
BOTH the folder structure AND the upload dropdown. Data remap over every existing
`TenderDocumentLink.category` — **every one of the 11 existing values must map to exactly one
new path, with zero orphans.** `Tender Documents` → `1. Plans, Scopes & Specs`, `Submissions`
→ `3. Estimates & Calcs`, `Other` → `7. Other/`. **Extend
`normaliseDocumentCategory`'s alias map, never replace it.**

**Gate:** requires S2 (naming settled before templating).
**gate_allow:** `migrations` (data remap on `TenderDocumentLink`).
**escalates:** `true` (data remap on production-shaped rows).
**Primary artifact:** `apps/api/src/modules/tender-documents/tender-document-categories.ts`
containing the new unified structure.

### TFM-S4 — Nested paths + per-client Quotes folders

**Prompt:** `docs/pr-prompts/pr-tfm-s4-nested-paths-and-dropdown-HOLD.md`

Teaches `ensureTenderCategoryFolder` (which currently assumes a single flat segment) to walk
nested paths. Adds the `Quotes/{Client}/` subfolders driven by `Tender.tenderClients`.
Front-end dropdown becomes a tree. A document carrying a legacy category must still render
under its mapped home, never blank.

**Gate:** requires S3.
**Primary artifact:** `apps/api/src/modules/platform/sharepoint.service.ts` containing
`ensureTenderQuoteClientFolder`.

### TFM-S5 — Provisioning visibility

**Prompt:** `docs/pr-prompts/pr-tfm-s5-provisioning-visibility-HOLD.md`

Stops swallowing per-category failures into a log line. Persists a per-tender provisioning
status (provisioned / partial / failed) with the failed-subfolder list. The tender page shows
the status; partial is actionable (retry button). **This is what makes autonomous filing
safe** — autonomous and silent is the failure mode that produced a tenders root with two
entries in it.

**Gate:** requires S4.
**gate_allow:** `migrations` (adds a status column + failure JSON; additive nullable;
`backfill: false`).
**Primary artifact:** `apps/api/prisma/schema.prisma` containing
`folderProvisioningStatus`.

### TFM-S6 — Legacy root + month walk

**Prompt:** `docs/pr-prompts/pr-tfm-s6-legacy-root-and-month-walk-HOLD.md`

Introduces a separately-configurable legacy root (env var + validated on startup), because
`sharepoint-legacy-copy.service.ts:287` wrongly assumes legacy and destination share a root.
The real legacy tree is `2. Quotes/Quotes 2026/{month}/` — nested one level deeper inside
month folders. Walks the month folders and enumerates every tender folder inside.

**Gate:** none (parallel to S1–S5).
**Primary artifact:** `apps/api/src/modules/admin-imports/sharepoint-legacy-copy.service.ts`
containing `legacyTendersRoot`.

### TFM-S7 — Copy precondition

**Prompt:** `docs/pr-prompts/pr-tfm-s7-copy-precondition-HOLD.md`

`plan` and `execute` must REFUSE any tender whose destination folder is not confirmed
present. Marco's "only after you confirmed the folders were created" becomes an enforced
precondition rather than a discipline. Adds `assertDestinationExists` before every copy
operation; the plan endpoint returns a per-tender readiness verdict.

**Gate:** requires S6.
**Primary artifact:** `apps/api/src/modules/admin-imports/sharepoint-legacy-copy.service.ts`
containing `assertDestinationExists`.

### TFM-S8 — The 2026 copy

**Prompt:** `docs/pr-prompts/pr-tfm-s8-copy-2026-HOLD.md`

Produces the exact per-tender copy list for 2026 tenders and writes it to
`docs/migration-runs/tender-folder-copy-2026.md` (committed to the repo as the audit trail).
**Marco runs `execute`.** The prompt states in bold: **automation must never remove the
do-not-merge label; copy only — never move, never delete; 2026 only.**

**Gate:** requires S7 (precondition) AND S2 (naming settled).
**escalates:** `true` (Marco runs execute; leave PR unmerged for review).
**Primary artifact:** `docs/migration-runs/tender-folder-copy-2026.md` present on main.

**Ordering that matters:** S8 must land AFTER S2. If the copy runs before the folder naming
is final, every copied file lands in a folder that S2 then renames, and the whole migration
is done twice across a live company library.

### TFM-S9 — Backfill and cleanup

**Prompt:** `docs/pr-prompts/pr-tfm-s9-backfill-and-cleanup-HOLD.md`

Re-runs the tender-folder backfill (`admin-imports/tender-folders/backfill`) so every
existing tender gets the new S3/S4 structure. Produces
`docs/migration-runs/tender-folder-cleanup-list.md` listing `T260814-XXXX-Rev1` and
`__connection_probe__` for Marco to delete by hand. **Removing anything from the live
library is Marco's action** — this slice produces the list, does not delete.

**Gate:** requires S8.
**escalates:** `true` (touches production-shape data through the re-run).
**Primary artifact:** `docs/migration-runs/tender-folder-cleanup-list.md` present on main.
