## The target model - state it in the plan exactly like this

Root stays `1. Operations/1. Tenders/` (already the configured mapping; no config change).

    1. Operations/1. Tenders/
        T260817 - Northshore/                    (T-YYMMDD then project; NO Rev, NO client)
            1. Plans, Scopes & Specs/
                01. Drawings/
                02. Specifications/
                03. Registers & BoQ/
                04. As Builts/
            2. Photos/
            3. Estimates & Calcs/
                Superseded/
            4. Suppliers/
            5. Compliance, WHS & Asbestos/
            6. Correspondence/
            7. Other/
            Quotes/
                {Client A}/                      (one per TenderClient)
                    Superseded/
                {Client B}/
            Project Record.docx

Two properties of this shape that the plan must call out explicitly:

1. **The folder name contains no Rev number, so a revision bump cannot strand it.** This is not a
   nicety - see the defect below.
2. **The client appears only under `Quotes/`.** Shared project material is stored once; each
   client's pricing stays separate. This is D36 and it is also a confidentiality property.

## A live defect this cluster must fix

Marking a revision renames `tenderNumber` in place. `ensureTenderCategoryFolder` then builds a path
from the NEW number, fails to find the old folder, and **creates a fresh one - stranding every
document filed before the revision, silently.** This exists on main today, independent of this work.
It is SLICE 2's first job and the plan must name it as a defect, not an improvement.
